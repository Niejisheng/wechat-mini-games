# 休闲益智小游戏

一个使用微信小游戏原生 Canvas API 开发的轻量小游戏合集，当前包含扫雷和数独两个入口。项目优先保持规则清晰、操作直接和视觉克制，并为后续加入更多小游戏预留统一接口。

## 当前内容

- 扫雷：翻开方块、长按插旗、数字格快速展开，并提供胜负提示、重玩和难度选择。棋盘固定为 9 列，难度通过增加行数和雷密度提升：容易 9×9/10 雷、中等 9×11/17 雷、标准 9×13/25 雷、困难 9×15/38 雷、极难 9×15/45 雷。失败时会播放短促反馈、冻结画面、爆炸当前地雷，并依次揭示其他未插旗地雷；通关时会播放多层庆贺动画。
- 扫雷首次点击安全：棋盘在第一次翻开时重新布雷，首击格及其周围格都会排除地雷；后续操作使用同一张棋盘。
- 数独：已接入手机 Canvas 版本的基础玩法。包含 9×9 棋盘、寻找数字、候选位置、笔记模式、长按排除/恢复、撤销和计时。

数独的核心特色是“寻找数字”：点击顶部 1–9 的数字后，棋盘会用淡橙色显示该数字的可能位置，数字卡片角标显示剩余数量。寻找状态下点击空白格只改变输入目标，候选色块保持不变；点击已有数字才会退出寻找状态并恢复普通的关联格提示。笔记、手动排除、正式输入和撤销会保持联动。

## 运行

1. 安装并打开微信开发者工具。
2. 选择“导入项目”，项目目录选择本仓库根目录。
3. 使用项目配置中的小程序 AppID，或按需替换为自己的 AppID。
4. 在开发者工具中编译并预览。

项目入口为 `game.js`，游戏全局配置位于 `game.json`，图标资源位于 `assets/icons/`。

## 验证

规则模块可以直接使用 Node.js 运行测试：

```sh
node tests/minesweeper.logic.test.js
node tests/sudoku.logic.test.js
node tests/app.registry.test.js
node --check game.js
node --check src/games/minesweeper/logic.js
node --check src/games/sudoku/logic.js
```

微信开发者工具中的画布布局、触摸命中区域和动画仍需要在模拟器或真机中体验验证。

## 界面设计风格

扫雷界面参考 **Minesweeper: The Clean One**，采用克制、安静的极简扁平风格：轻量借鉴 Material Design 的清晰层级和圆角，但避免厚重组件感。整体应清爽、低干扰，让棋盘成为视觉中心。

- **留白与布局：** 优先居中布局，保留充足呼吸空间；信息只在需要时出现，避免拥挤和无意义装饰。
- **配色：** 以白色或近白背景、灰色文字和一种低饱和蓝色作为主色。颜色数量尽量少，状态色仅用于表达必要反馈。
- **形状与细节：** 使用简洁几何形状、轻柔圆角和细线分隔；避免渐变、厚阴影、强描边和复杂纹理。
- **棋盘：** 视觉权重最高。格子保持扁平、边界清楚但不抢眼，不使用传统扫雷的浮雕或 3D 按钮效果。
- **图标：** 采用清晰、简练的线性或纯色几何图标，统一尺寸与视觉重量；避免拟物图标和多余装饰。
- **按钮：** 轻量、圆角、易识别。优先细线描边与柔和主色反馈，不添加厚重投影。
- **文字：** 使用清晰的无衬线字体，层级简明，字重柔和；避免大段说明和过强的标题装饰。
- **动效：** 短促、轻柔、服务于操作反馈；不遮挡棋盘，不改变玩家对格子状态的判断。

新增界面或调整视觉时，优先复用现有的颜色、圆角、图标和间距习惯。若某个装饰不能帮助识别状态、理解操作或建立层级，就不添加。

## 项目结构

```text
├── assets/icons/              # 界面图标
├── src/app/game-registry.js   # 合集游戏注册表
├── src/app/game-session.js    # 游戏统一生命周期接口
├── src/shared/canvas.js       # 通用 Canvas 绘制工具
├── src/games/minesweeper/
│   ├── logic.js               # 扫雷纯规则与棋盘数据
│   ├── controller.js          # 扫雷触摸、长按与结果页输入
│   ├── game.js                # 扫雷游戏会话工厂
│   └── view.js                # 扫雷棋盘、动画与结果绘制
├── src/games/sudoku/
│   ├── logic.js               # 数独候选、笔记、排除、撤销与完成判断
│   ├── controller.js          # 数独触摸、长按和数字输入
│   ├── game.js                # 数独游戏会话工厂
│   └── view.js                # 数独棋盘、候选区和键盘绘制
├── tests/                     # 可在 Node.js 中运行的规则测试
├── game.js                    # 当前入口、Canvas 绘制与页面交互
├── game.json                  # 小游戏全局配置
└── project.config.json        # 微信开发者工具项目配置
```

项目采用按游戏隔离的结构。游戏注册表负责首页元数据和游戏工厂，游戏会话统一提供 `enter`、`exit`、`draw`、`onTouchStart` 和 `onTouchEnd` 生命周期。每个游戏的规则、视图、输入控制和运行时状态都位于自己的目录中，`game.js` 只负责 Canvas 初始化、首页、页面切换和会话转发。

## 后续开发约定

修改已有游戏时，优先只查看和修改对应目录：

```text
src/games/minesweeper/   # 扫雷
src/games/sudoku/        # 数独
```

规则修改放在 `logic.js`，Canvas 绘制放在 `view.js`，触摸和长按放在 `controller.js`，状态、计时器、动画调度和生命周期放在 `game.js`。除非修改公共接口、首页或共享工具，否则不需要了解其他游戏的内部实现。

新增游戏时，创建如下目录：

```text
src/games/new-game/
├── logic.js
├── controller.js
├── view.js
└── game.js
```

然后在 `src/app/game-registry.js` 注册游戏名称、描述、图标元数据和 `create` 工厂。首页会根据注册表自动生成入口，会话层会根据工厂创建游戏实例。

跨电脑继续开发时，先阅读本 README 的项目结构和本节约定，再运行规则测试和语法检查：

```sh
node tests/app.registry.test.js
node tests/minesweeper.logic.test.js
node tests/sudoku.logic.test.js
node --check game.js
```

Canvas 布局、触摸命中区域、长按和动画仍需要在微信开发者工具或真机上验证。

数独当前使用固定初始题目，题目生成、难度切换、存档和完整通关反馈会在基础交互稳定后继续移植。
